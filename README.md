# 🧥 FashionDemon — Платформа электронной коммерции и управления заказами (OMS)

Проектирование и реализация масштабируемого бэкенд-сервиса интернет-магазина одежды с транзакционной обработкой заказов, контролем складских остатков и ролевой JWT-аутентификацией.

---

## 📌 О проекте и бизнес-контекст

**FashionDemon** — специализированный E-commerce сервис для ритейла брендовой одежды. Проект направлен на автоматизацию ключевых цепочек B2C-продаж: от навигации по многоуровневому каталогу до фиксации финансовых транзакций и отслеживания статусов доставки.

> **Роль системного аналитика в проекте:**
> Сбор и формализация требований (FR/NFR) ➔ Проектирование модели данных (PostgreSQL) ➔ Проектирование жизненного цикла заказа (State Machine) ➔ Разработка спецификации контрактов REST API ➔ Анализ граничных сценариев (гонки за остатки, историчность цен).

---

## 🎯 Бизнес-задачи и ключевые требования

### 1. Функциональные требования (FR)
* **Аутентификация и безопасность:** регистрация клиентов, безопасная аутентификация через JWT, разграничение доступа к пользовательским и административным операциям.
* **Каталог и номенклатура:** структурирование товаров по категориям, поддержка параметров (размеры, описания, цены), поиск и фильтрация.
* **Управление корзиной и чекаутом:** оформление заказа с валидацией наличия достаточного количества единиц на складе.
* **История заказов:** предоставление клиенту детализированной истории покупок с фиксированной стоимостью на момент сделки.

### 2. Нефункциональные требования (NFR)
* **Целостность данных (Data Integrity):** исключение продажи отсутствующих товаров (Overselling) за счет транзакционности операций в СУБД.
* **Производительность:** время отклика API на операции чтения каталога $\le 50$ мс за счет эффективного индексирования внешних ключей.
* **Масштабируемость:** сервисно-ориентированная архитектура на Go с возможностью горизонтального масштабирования в Docker-контейнерах.

## 🔄 Жизненный цикл заказа (Order State Machine)

В системе спроектирован строгий конечный автомат состояний заказа, исключающий невалидные переходы:

* `CREATED` (Заказ сформирован, бронирование остатков на складе)
  └──> `PAID` (Оплата подтверждена, заказ передан на сборку)
        └──> `SHIPPED` (Заказ передан в службу доставки)
              └──> `COMPLETED` (Товар успешно получен клиентом)
* `CANCELLED` (Отмена заказа: доступна из статусов `CREATED` и `PAID`; при отмене запускается процедура возврата зарезервированного товара на склад).

## 🗄️ Проектирование модели данных (Схема БД)

Реляционная база данных декомпозирована в 3-й нормальной форме (3NF). 

### Аналитические решения на уровне данных:
1. **Историчность цен (Price History Pattern):** В таблице `order_items` поле `price_at_purchase` сохраняет снимок цены товара на момент оформления заказа. Это исключает искажение финансовых отчетов и стоимости оформленного заказа при последующем изменении цены в общем каталоге `products`.
2. **Транзакционный декремент остатков:** Создание заказа и списание количества товара (`products.stock`) выполняются в рамках единой ACID-транзакции.
3. **Каскадность связей:** При удалении категории товарам выставляется `ON DELETE SET NULL`, сохраняя целостность каталога.

### Структура сущностей:
* **users:** учетные записи клиентов (`id`, `email`, `password_hash`, `role`, `created_at`).
* **categories:** классификатор товаров (`id`, `name`, `slug`).
* **products:** номенклатура склада (`id`, `category_id FK`, `title`, `description`, `price`, `stock_quantity`, `created_at`).
* **orders:** шапка документа заказа (`id`, `user_id FK`, `total_amount`, `status`, `created_at`).
* **order_items:** табличная часть заказа / спецификация (`id`, `order_id FK`, `product_id FK`, `quantity`, `price_at_purchase`).

## 🌐 Спецификация REST API (Контракты)

Взаимодействие реализовано по стандарту RESTful API. Передача данных осуществляется в формате JSON. Защищенные маршруты требуют передачи заголовка `Authorization: Bearer <JWT-token>`.

| Метод | Эндпоинт | Назначение | Доступ |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/auth/register` | Регистрация нового покупателя | Публичный |
| `POST` | `/api/v1/auth/login` | Аутентификация и выдача JWT-токена | Публичный |
| `GET` | `/api/v1/products` | Получение списка товаров с фильтрацией | Публичный |
| `GET` | `/api/v1/products/{id}` | Карточка конкретного товара | Публичный |
| `POST` | `/api/v1/products` | Добавление новой номенклатуры | Admin |
| `POST` | `/api/v1/orders` | Оформление заказа (с проверкой остатков) | Авторизованный |
| `GET` | `/api/v1/orders/my` | Просмотр истории личных заказов | Авторизованный |
| `PATCH` | `/api/v1/orders/{id}/status`| Изменение статуса заказа (переход стейта) | Admin |

## 🛠 Технологический стек

* **Язык разработки:** Go (Golang) — строгая типизация, высокая производительность и низкое потребление памяти.
* **СУБД:** PostgreSQL — реляционная целостность, поддержка строгих транзакций и ограничений (Constraints).
* **Слой работы с данными:** GORM — объектно-реляционное отображение, управление миграциями схемы.
* **Безопасность:** JWT (JSON Web Tokens), bcrypt (хэширование паролей), RBAC Middleware.
* **Инфраструктура:** Docker, Docker Compose (изоляция сервисов приложения, PostgreSQL и pgAdmin), Makefile.
